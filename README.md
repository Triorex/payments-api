# payments-api

A small payments service (FastAPI, Python 3.15) on the **Triorex paved road**. It is the
golden template for Python services: copy its layout and you get every security control.

| Endpoint | Purpose |
|---|---|
| `POST /payments` | Authorize a payment (strictly validated: amount, currency, merchant id, description) |
| `GET /payments/{id}` | Fetch one payment |
| `GET /payments?merchant_id=` | List a merchant's payments |
| `GET /healthz` | Liveness and readiness |
| `GET /openapi.json` | API schema, used by the DAST API scan |

## How security is wired in

This repo owns **one** CI file, [`.github/workflows/ci.yml`](.github/workflows/ci.yml). It calls the
central reusable workflows at a pinned commit; nothing security-related is implemented here.

| Stage | What runs (from the platform) |
|---|---|
| Pull request | Secrets, SAST (CodeQL, Semgrep, Bandit), dependency review, SCA, package curation, IaC, workflow security, Kyverno policy check, exception expiry → one required check `pr-security / gate` |
| Merge to main | Tests on Python 3.15 → Hadolint → build on Chainguard → Trivy + Dockle → OWASP ZAP API scan → SBOM, keyless signature, SLSA provenance |
| After build | Admission test: this signed image is admitted; an unsigned one is denied |
| Release | Signature and provenance re-verified, then promoted by digest: staging → production (AppSec approval) |
| Daily | Vulnerability triage (KEV + EPSS → issues with SLA), Scorecard, Dependabot |

## Choices worth knowing

- **Hash-locked dependencies.** `requirements*.txt` are generated by `uv pip compile --generate-hashes
  --exclude-newer <date>`; the build installs with `--require-hashes`, so a tampered or substituted
  package fails the build. `--exclude-newer` applies the 7-day release cooldown at lock time.
- **No package manager in the runtime image.** pip is removed after install. The first build
  surfaced CVE-2025-47273 in pip's vendored setuptools; removing pip removed the whole class.
  The image now scans with **zero** known CVEs.
- **Read-only, non-root, no shell.** Chainguard runtime image, `USER 65532`, read-only root
  filesystem, all capabilities dropped. Data lives in memory (the demo has no database).
- **Parameterised SQL only**, strict input validation, security headers, no server banner,
  no interactive docs.

## Local development

```sh
python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements.txt -r requirements-dev.txt
.venv/bin/python -m pytest -q
pre-commit install                      # gitleaks, Semgrep, Hadolint before every commit
docker build -t payments-api . && docker run --rm --read-only --tmpfs /tmp -p 8080:8080 payments-api
```

Risk exceptions go in [`.security/exceptions.yaml`](.security/exceptions.yaml) (AppSec review, 90-day maximum).
